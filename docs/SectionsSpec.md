커버(`GreenhouseCover.html`)의 톤을 나머지 여덟 영역에 그대로 옮긴다. 인사말과 사진은 이미 만든 것을 커버 기준으로 다시 맞추고, 남은 다섯 영역은 새로 만든다.
이전 스펙(`Spec.md`, `LaunchSpec.md`, `EditorialSpec.md`, `CollageSpec.md`, `ScrapbookSpec.md`)의 영역 기획은 이 문서로 대체한다.

> **오시는 길 ~ 참석 여부 배치**: 예식 안내(2-3)를 따른다(1-1). 톤·색·글꼴은 위 표(커버)대로다. 가운데 축에 한글 제목(`h2.section-title`, `clamp(28px, 8.5vw, 33px)`, 자간 -0.035em, 아래 여백 36px) → 15px 가운데 글. 영문 제목은 없다. 그림은 없다. `SectionKit.css`의 `.section--detail` 범위라 인사말·사진에는 영향이 없다. (예전에는 참고 이미지 `docs/references/OliveLineStyle.webp`대로 제목 위에 그림을 두었다.)

동작(캘린더에 추가, 지도 앱, 보내기, 청첩장 보내기, 주소 복사)은 키트의 **알약 버튼** `.pill`·`.pill--line`이다.
**크레파스 밑줄**(`--pencil` 연필색, 검은 면에서는 종이색. 두 번 겹쳐 그은 선)은 누르는 것 중 복사되는 글자(주소, 계좌번호)에만 쓴다. 고르기 전 선택지 단어의 연필 밑줄과 이름 칸의 선은 그대로 둔다.
고른 항목은 **크레파스 동그라미**로 두른다. 이 세 가지가 전 영역 공통 조작 표시다.

## 1-1. 일시 영역을 기준으로 맞춘 공통 규칙 (사용자 요청, 2026-11-24)

오시는 길·마음 전하실 곳·참석 여부·마무리는 예식 안내(2-3)의 배치와 글자 크기를 따른다. 이 절이 아래 영역별 설명보다 우선한다.

- **영역 그림.** 예식 안내·오시는 길·마음 전하실 곳·참석 여부는 맨 위에 커버 온실과 같은 붓 터치의 작은 그림을 하나씩 둔다(사용자 요청: 전체가 비어 보임). 배정과 만드는 법은 3절. 그 밖의 크레파스 표시는 선(달 아래), 동그라미(고른 항목), 밑줄(누르면 복사되는 글자)이다.
- **제목.** 영문 제목은 쓰지 않는다(사용자 요청). 오시는 길·마음 전하실 곳·참석 여부는 한글 이름이 제목이다(`h2.section-title`, Archivo/Noto Sans KR 500, `clamp(28px, 8.5vw, 33px)`, 자간 -0.035em, 아래 여백 36px). 제목 아래 따로 두던 한글 줄(`.section-kicker`)은 없앤다. 예식 안내와 마무리는 제목이 없다.
- **가운데 축.** 모든 줄을 가운데 정렬한다. 양 끝에 마주 보게 놓는 `.pair` 배치는 커버에만 남기고 이 네 영역에서는 쓰지 않는다. 짝(신랑측·신부측, 선택지)은 가운데에 나란히(간격 28px 안팎) 둔다.
- **글자 크기** (예식 안내와 같은 단계): 큰 글자 `clamp(22px, 6.6vw, 26px)` Archivo 500(장소 이름, 인원 숫자) / 본문 15px, 줄 높이 1.95 / 작은 라벨 12px 보조색 / 버튼 14.5px 500.
- **영역 여백.** 위아래 60px(예식 안내와 같음). 마무리는 60·80.
- **버튼 `.pill`** (키트): 동작은 밑줄 글자가 아닌 알약 버튼. 높이 46px, 좌우 26px, `border-radius: 999px`, 잉크색 면(`--ink`)에 반대색 글자(`--pill-text`: 흰 종이에서는 종이색, 검은 면에서는 `#161616`), 14.5px 500, 테두리·그림자 없음, 초점은 2px 잉크색 외곽선(바깥 3px), `disabled`는 불투명도 0.35. 보조 동작은 `.pill--line`: 면 없이 1px 잉크색 테두리, 잉크색 글자, 높이 44px, 좌우 18px.
  - `.pill`: `캘린더에 추가`, 참석 여부 `보내기`, 마무리 `청첩장 보내기`.
  - `.pill--line`: 지도 앱 세 개(한 줄, 간격 8px, 320px에서도 한 줄), 마무리 `주소 복사`.
- **밑줄은 복사되는 글자에만.** 주소와 계좌번호는 글자 자체를 눌러 복사하므로 크레파스 밑줄(`.crayon-link`)을 그대로 둔다. 고르는 항목(신랑측·신부측, 참석 선택지)은 크레파스 동그라미 그대로다.
- 영역별 차이
  - 오시는 길: 제목 → 지도 → 장소 이름 `식물관PH`(큰 글자) → 주소 한 줄(누르면 복사, 15px) → 지도 앱 버튼 줄 → 교통(항목 이름 12px 보조색, 아래 15px 문장, 모두 가운데).
  - 마음 전하실 곳: 제목 → 안내 문장 → `신랑측` `신부측` 가운데 나란히 → 계좌(이름 12px 보조색, 아래 계좌번호 15px).
  - 참석 여부: 제목 → 선택지 줄들(가운데 나란히) → 이름 칸(가운데 정렬 글자) → 인원(라벨 12px, 숫자 큰 글자) → `보내기` 버튼.
  - 마무리: 우표 → 글 → `청첩장 보내기`, 그 아래 `주소 복사` 버튼을 가운데에 세로로(간격 10px). 복사 안내 글자로 버튼 폭이 바뀌어도 줄이 밀리지 않게 세로로 둔다.

## 2. 영역별 기획

### 2-0. 받는 사람 이름 링크 (`?to=이름`)

사람마다 다른 링크를 보내 커버에 받는 사람 이름을 띄운다(사용자 요청). 서버·명단 없이 링크 주소에만 이름을 담는다(저장소가 공개라 하객 명단을 커밋하지 않는다).

- 링크: `https://jinyongharim.com/?to=민지`. `to`가 없거나 비면 지금과 똑같다.
- 이름 읽기(키트 `SectionKit.js`의 `window.InvitationKit.getGuestName()`): `to` 값의 앞뒤 공백을 지우고 안쪽 공백은 하나로, 12자(글자 단위)까지. 화면에는 `textContent`로만 넣는다.
- 커버: 손글씨 `for 민지`의 `for`가 `WEDDING INVITATION`의 마지막 두 글자 `ON` 아래쪽에 살짝 겹치게 둔다(왼쪽 끝을 `ON` 시작점, 제목 끝에서 1.9em 안쪽에 맞추고 제목 높이의 24% 아래에서 시작, 왼쪽 끝을 축으로 6° 기울임). 이름은 제목 끝 너머 오른쪽 여백으로 이어진다. 이름이 길어 커버 오른쪽 끝(8px 안쪽)을 넘으면 넘친 만큼만 왼쪽으로 당긴다(손글씨 글꼴이 실제로 도착한 뒤와 화면 크기가 바뀔 때 다시 잰다). 커버 카드는 `overflow-x: clip`이라 당기기 전에도 가로 스크롤이 생기지 않는다. 글자는 붉은 크레파스색 `#b02a33`(달력 6일 동그라미와 같은 색). `for`는 Homemade Apple(제목 글자의 0.96배, 사용자 요청으로 처음 0.8배의 1.2배. Google Fonts, 이름이 있을 때만 불러옴). 이름은 나눔손글씨 여름글씨(`for`의 1.95배, 처음 크기(제목의 1.44배)의 1.3배, 획을 0.9px 같은 색으로 덧그려 `for`와 굵기를 맞춤). 사용자가 견본(Google Fonts 12종, 나눔손글씨 3종) 중에서 고르고 원본 TTF를 줬다. 여름글씨는 `docs/cover-studies/fonts/NanumYeoReumGeurSsi-ksx1001.woff2`(KS X 1001 한글 2,350자 + 영문·숫자·기호, 약 510KB)를 `@font-face`로 등록해 두며, 브라우저는 이름이 화면에 나올 때만 받는다. 그 밖의 드문 한글은 기기의 손글씨 글꼴(`cursive`)로 나온다. 글꼴 파일은 `scripts/BuildGuestFont.py <원본 TTF>`로 만들고, 저작권 표기와 출처·라이선스 안내는 같은 폴더 `README.md`에 둔다(네이버가 무료로 배포하는 클로바 나눔손글씨, 조건은 네이버 라이선스 원문을 따른다). `BuildSite.py`는 페이지에 적힌 `fonts/*.woff2`를 복사한다. 이름이 있을 때만 제목에 `title--guest`를 붙여 아래 신랑·신부 이름 줄을 내려(위 여백 2.6em) 손글씨와 부딪히지 않게 한다. 제목(`h1`)의 `aria-label` 끝에 `, for 민지`를 붙인다.
- 참석 여부: 이름 칸이 비어 있으면 같은 이름을 미리 채운다(하객이 고칠 수 있음).
- 공유·복사: 마무리의 `청첩장 보내기`와 `주소 복사`는 `to`를 뗀 주소(`window.InvitationKit.getShareUrl()`)를 쓴다. 받은 사람이 다시 퍼뜨려도 자기 이름이 붙지 않는다.
- 카카오톡 미리보기 카드(`og:*`)는 모두 같다(정적 사이트라 사람마다 바꿀 수 없음).
- 링크를 만드는 도구 페이지는 따로 만든다(아직 없음).

### 2-1. 인사말 (제목 없음)

인사말은 **검은 면**(`#000` + 검은 종이 질감, 사용자 요청)이다. 구성은 우표 한 장 → 종이색 글자의 가운데 정렬 인사말. 제목과 서명 줄은 없다.

- 배경: `#000` 위에 검은 종이 질감 `textures/paper-black.png`(400px 타일을 200px로 깔음). 질감이 오기 전에는 순수한 검정. 화면 전체 폭으로 깔고, 내용은 다른 영역과 같은 440px 기둥 안에 둔다. PC에서는 종이색 페이지를 가로지르는 검은 띠가 된다. 위(커버)·아래(사진 영역)와는 반듯한 수평선으로 끊긴다(그라데이션·그림자 없음). `<section>`에 `data-tone="dark"`.
- 우표: 사용자가 준 흰 종이 우표 이미지(`textures/stamp-frame.png`, 595×860, 톱니 포함, 바깥과 구멍은 투명) 한 장 안에 종이 청첩장 표지와 같은 사진 두 장을 같은 구도로 위아래로 넣는다(컬러). 위는 `photo-12`(역광 들판에서 신랑이 웃는 신부의 볼에 얼굴을 댄 모습, 얼굴·어깨), 아래는 `photo-04`(파란 하늘 아래 나란히 서서 신부가 신랑을 올려다보는 상반신, 부케 포함). 사진 창은 종이 가장자리에서 네 변 모두 62px(원본 픽셀) 안쪽: 톱니가 18–19px 파고들어 톱니 안쪽으로 약 43px(종이 폭의 7%) 흰 여백이 남는다. 이 창을 같은 크기 두 칸(각 471×361)으로 나누고 사이에 종이 흰 띠 14px(종이 폭의 2.4%)를 둔다. CSS로는 두 칸 모두 왼쪽 10.420%, 폭 79.160%, 높이 41.977%, 위 칸 top 7.209%, 아래 칸 top 50.814%. 칸이 사진을 잘라 보이고, 사진은 칸 폭 기준 %로 확대·이동한다(12번 원본 x 520–1060·y 294–708, 04번 원본 x 510–1090·y 430–874를 칸에 꽉 채움).
- 크기: 우표 폭 `clamp(86px, 25.6vw, 112px)`(390px 화면 약 100px, 320px 화면 86px), `aspect-ratio: 595 / 860`으로 이미지가 오기 전에도 자리를 잡는다.
- 여백: 영역 위 56px, 아래 60px(검은 면이 답답하지 않게 흰 영역보다 조금 넉넉히), 우표와 인사말 사이 52px.
- 글자: 종이색(`#fbfbf8`), `.prose` 크기 그대로. 인사말 문단이 마지막 요소다.
- 등장 효과 없음. 예전의 CSS mask 우표 두 장과 크레파스 외곽선은 뺐다.
- 인사말은 6줄 이내, 한 줄 16자 안팎으로 끊는다. 문구는 초안이라 확정이 필요하다.

### 2-1b. 두 사람 (제목 없음) — `Families.html`

### 2-2. 사진 (다시 맞춤) — 스크랩북 페이지 (`PhotosScrapbook.html`)

사용자가 준 스크랩북 참고 이미지처럼, 사진 14장을 크기가 서로 다른 액자로 종이 위에 비대칭으로 흩어 놓는다. 이전의 세 줄 필름 스트립(`PhotosFilm.html`)을 대신한다(필름 스트립은 지움). 사진 영역에는 글자를 넣지 않는다(사용자 요청, 참고 이미지의 캡션도 넣지 않는다).

- 격자·촘촘한 모자이크가 아니다. 가운데에 거의 화면 폭의 큰 가로 사진(대표 사진) 한 장, 그 위아래로 작은 사진들이 좌우로 엇갈리고 사이 여백은 고르지 않게 넉넉하다.
- 사진마다 커버 크레용 그림과 같은 손그림 사각형 테두리. 색은 검정에 가까운 무채색 회색 `#333333`(초록·푸른 기 없음, 사용자 요청), 굵은 줄(2.6px)과 옅은 줄(1.2px, 반투명) 두 번, 모서리가 살짝 삐져나간다. 데이터 URI SVG 네 가지를 번갈아 써서 찍어낸 느낌을 피하고, `preserveAspectRatio='none'` + `non-scaling-stroke`로 사진 크기에 맞춰 늘어난다. 덮개는 `pointer-events: none`. 그림자·회전·둥근 모서리 없음.
- 모든 사진은 화면 안에 둔다(크레파스 테두리가 잘리지 않게, 사용자 요청). 가로 스크롤은 생기지 않는다.
- 여백에 장식 그림(별·잎·꽃 등)을 넣지 않는다(사용자 요청). 사진과 크레파스 테두리만 둔다.
- 배치는 영역 폭 기준 컨테이너 단위(cqw)로 잡아 375–440px에서 같은 모양으로 늘고 준다. 영역 폭은 다른 영역과 같이 최대 440px, 데스크톱에서 가운데.
- 비율은 칸마다 가로·세로를 섞어 정하고 `object-fit: cover`로 채운다. 가로 사진은 두 사람 위치에 맞춰 `--pos`로 잘라 쓴다. 누르면 원본을 크게 본다.

### 2-3. 예식 안내 (제목 없음)

- 남은 시간 `.countdown`: `DAYS HOURS MINS SECS` 네 칸, 숫자는 Archivo 큰 글자(시·분·초는 두 자리), 아래 작은 보조색 라벨, 칸 사이 `:`. 1초마다 갱신. 스크립트가 없거나 예식 시각(2027-03-06 17:00 한국 시간)이 지나면 숨긴다(`hidden`). 스크린리더에는 숨긴다(`aria-hidden`).
- `캘린더에 추가`: 밑줄 글자가 아닌 버튼 모양(사용자 요청). 키트의 `a.pill`(1-1): 잉크색 면에 종이색 글자, 알약 모양(`border-radius: 999px`), 높이 46px, 좌우 여백 26px, 글자 14.5px 500. 테두리·그림자 없음. 키보드 초점은 2px 잉크색 외곽선(바깥 3px). 이 영역에서 처음 만든 모양이고, 지금은 뒤 영역의 동작 버튼도 같은 `.pill`을 쓴다. 맨 아래.
  - 일정: `서진용 · 장하림 결혼식`, 2027-03-06 17:00–19:00(한국 시간. 끝 시각은 임시), 장소 `식물관PH`. 주소는 확인 전이라 넣지 않는다.

- 카카오페이·토스 송금 링크는 받으면 계좌 옆에 단어로 추가한다.

### 2-6. 참석 여부 — `참석 여부`

- 맨 위 그림 답장 카드와 연필(3절), 그 아래 24px 띄워 제목. 영역 맨 아래(폼 밖, 보낸 뒤에도 남음)에 꽃 단 의자 두 개 그림, 폼과 사이 40px. 1-1을 따라 가운데 축, 위아래 여백 60px.
- 구성: 제목 `참석 여부`. 그 아래 질문 하나에 한 줄. 선택지는 가운데에 나란히 놓은 두 단어(간격 28px), 고르면 크레파스 동그라미.
  1. `신랑측` `신부측`
  2. `참석해요` `마음만 보내요`
  3. 이름: 크레파스 밑줄 한 줄 위에 직접 입력, 글자는 가운데
  4. 인원: 12px 보조색 라벨 `인원` 아래 `−  1  +` (숫자는 큰 글자, 1–9명, 처음 값 1, 참석일 때만 보임)
  5. 식사: `식사해요` `식사 안 해요` (참석일 때만 보임). 참석을 골랐으면 식사도 골라야 보내진다
  6. `보내기` — 키트 알약 버튼(`button.pill`). 스크립트가 돌기 전에는 `disabled`(불투명도 0.35). 보낸 뒤에는 폼 자리에 "전해졌어요. 고맙습니다." 한 문장만 남는다. 오류·결과 문장은 15px.
- 입력칸 상자, 필수 표시(*), 드롭다운은 쓰지 않는다. 선택지 단어는 평소 연필 밑줄, 고르면 동그라미. 답하지 않은 줄(이름, 참석일 때 식사 포함)은 밑줄만 붉은색으로 바뀐다.
- 저장: 구글 앱스 스크립트(`scripts/RsvpSheet.gs`)로 구글 시트에 한 줄씩 기록 (무료, 두 분이 시트로 바로 확인). 같은 기기에서 같은 이름으로 다시 보내면 덮어쓴다 (한 기기로 다른 이름을 보내면 새 줄). 주소(`RSVP_ENDPOINT`)를 넣기 전에는 저장하지 않고 "시안이라 아직 저장되지는 않아요."라고 알린다.

### 2-7. 마무리 (제목 없음)

인사말과 처음·끝이 짝이 되는 **검은 면**이다. 우표 한 장 → 종이색 마지막 인사 → 위아래로 쌓은 버튼 두 개.

- 우표: 인사말과 같은 종이(`textures/stamp-frame.png`), 같은 크기·사진 창. 사진은 06번(서로 기대어 웃는 세로 사진) 한 장을 두 사람 머리부터 부케까지 잘라 넣는다.
- 마지막 인사: 인사말과 같은 15px 가운데 정렬. 제목과 그림은 없다.
- `청첩장 보내기`(`.pill`) 위, `주소 복사`(`.pill.pill--line`) 아래로 가운데에 쌓는다(간격 10px). 줄이 따로라 `복사했어요`로 글자가 바뀌어도 `청첩장 보내기`는 움직이지 않는다. 검은 면에서는 색이 뒤집혀 `.pill`은 종이색 면에 잉크색 글자, `.pill--line`은 종이색 테두리·글자다. `청첩장 보내기`는 휴대폰 기본 공유 창을 연다 (카카오톡 전용 공유는 카카오 앱 키가 있어야 해서 보류). 공유 창이 없는 브라우저에서는 `주소 복사`만 가운데에 남는다. 두 버튼 모두 받는 사람 이름(`?to=`)을 뗀 주소를 쓴다(2-0).
- 이름은 다시 적지 않는다. 제작 표기, 각주, 저작권 문구는 넣지 않는다.

## 3. 그림 배정

| 영역 | 그림 | 색 |
|---|---|---|
| 커버 | 반지, 온실 | 금, 초록·붉은색 |
| 인사말 | 없음 (우표 사진, 검은 면) | – |
| 사진 | 없음 (사진만, 글자 없음) | – |
| 예식 안내 | 맨 위 꽃 아치 (`illustrations/arch.png`) | 초록 잎, 붉은 꽃, 온실 틀 회색 |
| 오시는 길 | 맨 위 작은 온실 (`illustrations/greenhouse.png`) | 커버 온실과 같음 |
| 마음 전하실 곳 | 맨 위 꽃가지를 꽂은 봉투 (`illustrations/envelope.png`) | 상아색 봉투, 붉은 봉인 |
| 참석 여부 | 맨 위 답장 카드와 연필 (`illustrations/reply-card.png`), 맨 아래 꽃 단 의자 두 개 (`illustrations/chairs.png`) | 상아색 카드, 노란 연필, 나무색 의자 |
| 마무리 | 없음 (우표 사진, 검은 면) | – |

- 영역 그림은 사용자가 여러 시안(작은 아이콘 4종, 새 그림 12종) 가운데 고른 것이다. 커버와 같은 색(`GREENS`, `BLOOMS`, 온실 틀 `#7f8b8a`)과 같은 붓 터치(두 번 겹친 흔들리는 선, 흰 점 질감, 노란 꽃술)로 그린다.
- 그림 원본은 `docs/cover-studies/illustrations/Illustrations.html`(`?n=이름`으로 한 장씩 그림)이고, `node scripts/BuildIllustrations.mjs`가 240×150 그림을 3배(720×450) 투명 PNG로 찍어 같은 폴더에 저장한다. 결과 PNG를 커밋하고, `BuildSite.py`는 페이지에 적힌 `illustrations/*.png`만 복사한다.
- 화면에서는 `img.section-art`, 폭 192px·높이 120px, 가운데, 그림과 아래 제목(또는 일시 줄) 사이 24px. 장식이라 `alt=""`. 참석 여부 맨 아래 의자는 `img.section-art.section-art--end`(위 40px, 아래 0).
- 인사말·두 사람·사진·마무리에는 그림을 두지 않는다(우표·사진이 있음).

## 4. 만드는 방식

- 인사말은 기존 파일(`GreetingCard.html`)을 고치고, 사진은 `PhotosScrapbook.html`(스크랩북 페이지)로 새로 만들었다(예전 커버플로, 흩어 놓은 배치, 하트 모자이크, 필름 스트립은 지움).
- 새 영역은 `docs/cover-studies/`에 파일 하나씩: `CeremonyInfo.html`, `Directions.html`, `GiftAccounts.html`, `Rsvp.html`, `Closing.html`.
- `.section-title`(`.section--detail` 안에서 가운데 한글 제목), 알약 버튼 `.pill`·`.pill--line`, 크레파스 밑줄, 크레파스 동그라미, 복사 동작은 공용 키트(`SectionKit.css`, `SectionKit.js`)에 두고 모든 영역이 그대로 쓴다.
- `scripts/BuildInvitation.py`는 영역 목록(`SECTIONS`)을 순서대로 합치고 키트를 한 번만 넣는다.
- 순서는 한 영역씩 확정: 인사말 → 사진 → 예식 안내 → 오시는 길 → 마음 전하실 곳 → 참석 여부 → 마무리.
- 움직임은 `prefers-reduced-motion`일 때 끈다. 누르는 글자는 높이 44px 이상을 확보한다.
